基本概念

R01 · ROS 是操作系统吗？它到底是什么？"节点"是什么？

来源：第 1 章 · 第 1 步 · 加入 2026-11-05 · 复习记录：

答案

不是。ROS 是装在 Ubuntu 等系统上面的一套工具和库，官方说它是机器人各部分之间通信的"管道"（plumbing）。

节点（node）= 一个只干一件事的程序，比如读相机、找红球、驱动电机。节点之间通过有名字的话题（topic）传数据，彼此不需要知道对方是谁，所以换掉一个节点不影响别人；节点可以在同一进程、不同进程或不同电脑上。

口诀：后厨每个厨师只干一件事，做好就放传菜口。

R02 · ROS 2 从上到下分哪几层？换中间件（比如 Fast DDS 换成 Zenoh）要改你的代码吗？

来源：第 1 章 · 总图 1 · 加入 2026-11-05 · 复习记录：

答案

能力包（Nav2 / MoveIt 2 / ros2_control）→ 你的节点 → 客户端库 rclpy / rclcpp（你调用的 API）→ rcl（C 写的公共核心）→ rmw 接口（中间件"插座"）→ rmw 实现（"插头"：Fast DDS 默认、Cyclone DDS、Connext DDS、Zenoh）→ 传输（同进程 / 共享内存 / UDP）。旁边是 rosidl：把 .msg / .srv / .action 生成各层要用的代码。

不用改代码，设环境变量 RMW_IMPLEMENTATION 就能换。rmw 这层就是为了把用户代码和中间件隔离开。

口诀：节点写在上，rclpy 来调；rcl 往下是内部，中间件能换插头。

R03 · 一条消息从 talker 到 listener 要经过哪几步？两个节点要满足哪三个条件才能连上？忘了写 spin() 会怎样？

来源：第 1 章 · 总图 2 · 加入 2026-11-05 · 复习记录：

答案

建立连接（只做一次）：① 创建 publisher / subscription → ② 发现：中间件在同一 ROS_DOMAIN_ID 里自动广播，没有中心服务器 → ③ 匹配：话题名相同 + 消息类型相同 + QoS 兼容。

每条消息：④ publish(msg) → ⑤ 往下 rclpy → rcl → rmw → ⑥ 序列化成字节 → ⑦ 传输 → ⑧ 放进接收端的订阅队列 → ⑨ executor 在 spin() 里通过等待集（wait set）发现有数据 → ⑩ 往上、反序列化成对象 → ⑪ 调用 callback(msg)。

忘了 spin()：消息一直躺在队列里，回调永远不会执行。QoS 不兼容：连不上，只打一条警告。

口诀：先发现、再匹配；往下变字节，往上变对象；队列里等着，spin 才叫醒回调。

R04 · 话题、服务、动作、参数各在什么情况下用？各举一个机器人例子。

来源：第 1 章 · 第 2 步 · 加入 2026-11-05 · 复习记录：

答案
  • 话题：数据源源不断、单向、多对多，发的一方决定节奏。例：相机 30 Hz 发 /image、/joint_states。
  • 服务：一问一答，问的一方等着，必须很快结束。例：问 IK 解、问电量。耗时长的事不能用服务（没法中途取消）。
  • 动作：耗时长、有进度反馈、能取消 / 抢占。例："导航到厨房"、"去抓杯子"。
  • 参数：节点自己的设置，不改代码就能调，运行中也能改。例：要找的颜色、最高车速、use_sim_time。

另：一个服务名 / 动作名只能有一个 server；话题的发布者、订阅者数量不限。

口诀：流水用话题，问答用服务，长活用动作，设置用参数。

R05 · ROS 1 和 ROS 2 在结构上最大的区别是什么？ROS 2 为什么要另起一套、为什么选 DDS？

来源：第 1 章 · 第 3 步 · 加入 2026-11-05 · 复习记录：

答案

最大区别：ROS 1 有一个中心 master（roscore），所有节点先去它那登记再找彼此；ROS 2 没有 master，靠 DDS 的分布式发现自动找到彼此。

另起一套的原因：ROS 1 围着 PR2 的六个前提设计（单台机器人、工作站级电脑、不要求实时、网络很好、学术研究、什么都不规定），后来的多机器人、嵌入式、实时、差网络、产品化需求都满足不了；在 ROS 1 上改太伤筋动骨，会弄坏大家在用的系统，所以 API 不兼容，靠桥接（bridge）共存。

选 DDS：自己维护的代码少；有成文的工业标准；自带分布式发现；已有生产系统在用。代价是要在 DDS 的框架里干活，所以用 rmw 把它隔离在下面，后来还加了 Zenoh。

口诀：小饭馆开连锁：去掉领班（master），借用 DDS，加上 QoS。

命令行

R06 · 每个新终端第一件事做什么？ros2 run turtlesim turtlesim_node 里两个词各是什么？节点名一定等于可执行文件名吗？

来源：第 2 章 · 第 1 步 · 加入 2026-11-13 · 复习记录：

答案

先 source /opt/ros/lyrical/setup.bash：告诉这个终端 ROS 装在哪，否则 ros2: command not found。

turtlesim 是包名（工具箱），turtlesim_node 是包里的可执行文件名（一件工具）。节点名不一定相同：turtlesim_node 跑起来叫 /turtlesim，turtle_teleop_key 叫 /teleop_turtle。用 ros2 node list 查节点名，ros2 node info 查它的发布 / 订阅 / 服务 / 动作；--ros-args --remap __node:=新名 改名。

口诀：包是工具箱，可执行是工具，节点名是工牌。

R07 · 排查一个话题，常用哪四个命令？各看什么？

来源：第 2 章 · 第 2 步 · 加入 2026-11-13 · 复习记录：

答案
  • ros2 topic echo <话题>：看内容（它自己是一个新订阅者，会让订阅者计数 +1）；
  • ros2 topic info <话题> [-v]：看类型、发布者 / 订阅者数，-v 再看节点名和 QoS；
  • ros2 topic hz <话题>：看频率（是 hz 自己收到的频率，受负载和 QoS 影响）；
  • ros2 topic pub [--once | --rate N] <话题> <类型> "<YAML>"：自己发。

另：ros2 interface show <类型> 看消息格式；rqt_graph 画出整张计算图。

口诀：echo 看内容，info 看谁连着，hz 看频率够不够，pub 自己发。

R08 · 怎么调用一个服务？怎么让节点每次启动都用同一组参数？

来源：第 2 章 · 第 3 步 · 加入 2026-11-13 · 复习记录：

答案

服务：ros2 service list -t 找名字和类型 → ros2 interface show <类型> 看格式（--- 上是请求、下是回复）→ ros2 service call <名字> <类型> "<YAML 请求>"。例：ros2 service call /spawn turtlesim_msgs/srv/Spawn "{x: 2, y: 2, theta: 0.2, name: ''}"。

参数：ros2 param dump /节点 > 文件.yaml 存下来（格式是 /节点: ros__parameters: {名: 值}），启动时加 --ros-args --params-file 文件.yaml；运行中可以 ros2 param load 灌回去，或 param set 单个改。param set 底层调用的就是节点自带的 …/set_parameters 服务。

口诀：先 list 再 show 后 call；dump 存、params-file 载。

R09 · 动作接口文件有几段？一个动作目标有哪三种结局？

来源：第 2 章 · 第 4 步 · 加入 2026-11-13 · 复习记录：

答案

三段，用两条 --- 隔开：目标（goal）/ 结果（result）/ 反馈（feedback）。例 RotateAbsolute：theta（要转到的绝对朝向，弧度）/ delta（实际转过的角度）/ remaining（还剩多少）。

结局：成功（SUCCEEDED）；客户端取消（canceled，如按 F）；服务端放弃（aborted，如 turtlesim 收到新目标就放弃旧的）。新目标来了旧目标怎么办由每个服务端自己定，ROS 不统一规定。每个目标有唯一 ID。

命令：ros2 action send_goal <名> <类型> "<YAML>" --feedback。

口诀：动作三段（目标、结果、反馈），三结局（成功、取消、放弃）。

R10 · ROS 2 日志有哪五个级别、默认去哪三个地方？为什么要有 /rosout？

来源：第 3 章 · 第 1 步 · 加入 2026-11-13 · 复习记录：

答案

级别从低到高：DEBUG < INFO < WARN < ERROR < FATAL；日志器只处理不低于设定级别的消息，默认 INFO。

三个去处：终端（stderr）、磁盘日志文件（~/.ros/log/，ROS_LOG_DIR 可改）、/rosout 话题。/rosout 汇集全机所有节点的日志，在任意一台电脑上用 rqt_console 订阅就能看全部，不用逐台登录。

调级别：--ros-args --log-level debug；高频回调里打日志要节流（Python throttle_duration_sec=，C++ RCLCPP_INFO_THROTTLE）。

口诀：五级三去处，高频要节流。

R11 · 一个 Python launch 文件最少由哪几部分组成？namespace= 有什么用？

来源：第 3 章 · 第 2 步 · 加入 2026-11-13 · 复习记录：

答案

入口函数 generate_launch_description()，返回 LaunchDescription([...]) 清单；清单里每个 launch_ros.actions.Node(package=, executable=, namespace=, output=) 相当于一条 ros2 run。运行：ros2 launch <包> <文件> 参数:=值。launch 也可用 XML / YAML 写。

namespace 给节点的所有名字加前缀：两个 turtlesim 分别在 turtlesim1、turtlesim2 下，话题变成 /turtlesim1/turtle1/cmd_vel 等，互不干扰。多台同型号机器人靠它分组。命令行等价写法：--ros-args -r __ns:=/turtlesim1。

口诀：一张清单起全家，命名空间分你我。

R12 · bag 的录、看、放三个命令？默认存储格式？回放时要注意什么？

来源：第 3 章 · 第 3 步 · 加入 2026-11-13 · 复习记录：

答案
  • 录：ros2 bag record -o <目录> --topics <话题...>（-d 按秒切分，-b 按大小切分）；
  • 看：ros2 bag info <目录>（读 metadata.yaml）；
  • 放：ros2 bag play <目录>（按原时间间隔重新发布，空格暂停；-i 同时放多个）。

默认存储 MCAP（老版本 SQLite），消息按 CDR 序列化字节存，录制不用反序列化。回放时要关掉被录话题的原始发布者，否则同一话题两个来源打架。还能录服务 / 动作（需节点开内省）。

用途：现场问题复现、示范数据集原始形态、离线测试感知节点。

口诀：录字节、存 MCAP、按原时间放，回放先关原发布者。

写代码

R13 · 工作区里有哪几个目录？overlay 和 underlay 是什么，source 的顺序和注意事项？

来源：第 4 章 · 第 1 步 · 加入 2026-11-13 · 复习记录：

答案

~/ros2_ws/src/ 放源码（你只动这里）；colcon build 生成 build/（中间文件）、install/（成品 + setup 脚本）、log/（构建日志）。

underlay = 已装好的 ROS（/opt/ros/lyrical）；overlay = 你的工作区，叠在 underlay 上，可用其中所有包，同名包 overlay 优先。

顺序：新开终端 → source /opt/ros/lyrical/setup.bash → source ~/ros2_ws/install/local_setup.bash（或直接 source install/setup.bash，它包含底层）。不要在编译用的终端里 source overlay，也不要在 source 了 overlay 的终端里编译。

口诀：先 source 底层再 source 上层，同名上层优先，新终端里 source。

R14 · 一个 Python ROS 包最少有哪些文件？package.xml 的依赖为什么要写全？构建系统分哪三层？

来源：第 4 章 · 第 2–3 步 · 加入 2026-11-13 · 复习记录：

答案

package.xml、setup.py（entry_points 里登记 命令名 = 包.模块:函数，否则 ros2 run 找不到）、setup.cfg、resource/<包名>（空标记文件）、<包名>/__init__.py。C++ 包：package.xml + CMakeLists.txt + include/ + src/。

依赖（<depend> / <build_depend> / <exec_depend> / <test_depend>）写全的原因：colcon 靠它排编译顺序，rosdep 靠它装系统库。

三层：构建工具（CMake / setuptools，编一个包）→ 构建辅助（ament，加 ROS 便利）→ 元构建工具（colcon，编一堆包、排顺序、并行）。常用：colcon build --symlink-install --packages-select <包>；rosdep install -i --from-path src --rosdistro lyrical -y。

口诀：package.xml 是身份证；rosdep 装依赖，colcon 排顺序。

R15 · Python 节点的最小骨架是什么？rclpy.spin(node) 起什么作用？

来源：第 5 章 · 第 1 步 · 加入 2026-11-13 · 复习记录：

答案 
class MyNode(Node):
    def __init__(self):
        super().__init__('my_node')
        # 在这里 create_publisher / create_subscription / create_timer / create_service
def main(args=None):
    try:
        with rclpy.init(args=args):
            rclpy.spin(MyNode())
    except (KeyboardInterrupt, ExternalShutdownException):
        pass

节点是事件驱动的：__init__ 只登记回调，spin 把控制权交给 executor，它发现定时器到点 / 有新消息 / 有服务请求，就调用对应回调。不 spin，回调永远不执行。创建出的对象要存到 self 上，否则被回收、功能停止。

口诀：继承 Node 起个名，init、spin 加 Ctrl+C。

R16 · 服务客户端为什么要用 call_async？在单线程 executor 的回调里用同步 call() 为什么会死锁？

来源：第 5 章 · 第 3 步 · 加入 2026-11-13 · 复习记录：

答案

call_async 立刻返回 future（凭条），回复到了由 executor 在 spin 中填入；主程序用 spin_until_future_complete(node, future)，回调里用 future.add_done_callback(...)。

死锁：回调里 call() 阻塞等回复；回复要靠 executor 取出来，而单线程 executor 正卡在这个回调里，没空去取。回调等回复、回复等回调结束。

改法：call_async + 完成回调；多线程 executor + 回调组（第 9 章）；Lyrical 的 AsyncNode 用 await client.call(req)。

口诀：拿凭条别干等；回调里不阻塞。

R17 · 节点参数怎么声明和读取？运行中参数被修改，有哪三种回调、各干什么？

来源：第 5 章 · 第 4 步 · 加入 2026-11-13 · 复习记录：

答案

self.declare_parameter('名', 默认值[, ParameterDescriptor(...)])（默认值决定类型，必须先声明再用）；读取 self.get_parameter('名').get_parameter_value().string_value（或 .value）。

  • pre-set（add_pre_set_parameters_callback）：生效前，可增改要设的参数列表；
  • on-set（add_on_set_parameters_callback）：生效前校验，返回 SetParametersResult(successful=False) 拒绝；不要有副作用，因为后面的回调可能还会拒绝；
  • post-set（add_post_set_parameters_callback）：成功后，更新成员变量、重新配置。

口诀：先声明再用；校验在 on-set，收尾在 post-set。

R18 · .msg 里怎么写数组、有界类型、默认值和常量？自定义接口包有什么硬性要求？

来源：第 6 章 · 第 1–2 步 · 加入 2026-11-13 · 复习记录：

答案

每行"类型 名字"。int32[] 不限长，int32[5] 定长，int32[<=5] 有上限，string<=10 字符串有上限（有界类型尺寸已知，利于实时预分配）。默认值放第三项：uint8 x 42；常量全大写用等号：int32 X=123。类型名大驼峰（MyMessage.msg），字段名小写下划线。

接口包必须是 ament_cmake；CMakeLists：find_package(rosidl_default_generators REQUIRED) + rosidl_generate_interfaces(${PROJECT_NAME} "msg/Num.msg" ... DEPENDENCIES geometry_msgs)；package.xml 三行：<buildtool_depend>rosidl_default_generators</buildtool_depend>、<exec_depend>rosidl_default_runtime</exec_depend>、<member_of_group>rosidl_interface_packages</member_of_group>。生成的代码 Python / C++ 都能用。能用标准消息就别自定义。

口诀：接口包只能 CMake，CMake 一句生成、package.xml 三行。

R19 · 动作在底层由哪些服务和话题组成？目标有哪些状态？

来源：第 6 章 · 总图与第 3 步 · 加入 2026-11-13 · 复习记录：

答案

三个服务：_action/send_goal（发目标，回接受 / 拒绝）、_action/cancel_goal（请求取消）、_action/get_result（提前请求，服务端做完才回复）；两个话题：_action/feedback（进度）、_action/status（所有在办目标状态）。名字以 _action/ 开头，默认隐藏。

状态机（只针对被接受的目标）：中间态 ACCEPTED → EXECUTING，取消时 CANCELING；终态 SUCCEEDED（成功）、ABORTED（服务端自己放弃）、CANCELED（应客户端要求取消）。服务端用 goal_handle.publish_feedback / succeed / abort / canceled；可选 goal_callback（接不接受新目标）、cancel_callback（同不同意取消）。

口诀：三服务两话题；三中间态三终态。

通信机制

R20 · QoS 有哪七个策略？Reliable 和 Best effort、Volatile 和 Transient local 各适合什么数据？

来源：第 7 章 · 第 1 步 · 加入 2026-11-13 · 复习记录：

答案

History（Keep last / Keep all）、Depth（队列深度）、Reliability（Reliable 丢了重传 / Best effort 丢了就丢）、Durability（Volatile 不保存 / Transient local 发布者保存最近消息，晚来的订阅者也能收到）、Deadline（相邻消息最大间隔）、Lifespan（消息多久过期）、Liveliness + Lease duration（发布者多久不报平安算挂了）。

高频传感器用 Best effort（Sensor data 预设：宁可丢帧也要最新，Reliable 在丢包时重传会让延迟越积越大）；指令、服务用 Reliable；地图、机器人描述等只发一次的用 Transient local（≈ ROS 1 latched）。默认：Keep last 10、Reliable、Volatile。ROS 2 的 Reliable 也基于 UDP，由 DDS 做确认重传。

口诀：历史、深度、可靠、持久，截止、寿命、活性。

R21 · QoS 兼容规则是什么？举两个最常见的"收不到消息"的坑，怎么排查？

来源：第 7 章 · 第 2–3 步 · 加入 2026-11-13 · 复习记录：

答案

"要求 vs 提供"：订阅者要求最低质量，发布者提供最高质量，每一项要求都不高于提供才连接。不兼容时不报错退出，只打 incompatible QoS 警告 / 触发事件，消息不传。

坑 1：发布者 Best effort（相机、雷达驱动），订阅者默认 Reliable → 连不上。改订阅为 qos_profile_sensor_data。 坑 2：/map 用 Transient local 只发一次，订阅者用 Volatile → 能连上但晚来收不到；两边都要 Transient local（发布者 Volatile、订阅者 Transient local 则连不上）。 Deadline / 租期：订阅者要求的时长不能比发布者提供的更短。

排查：ros2 topic info <话题> --verbose 看两边 QoS；命令行可 --qos-reliability best_effort。可挂 QoS 事件回调（deadline missed、incompatible QoS、liveliness changed），用 Deadline 实现指令超时停车。

口诀：要求不高于提供；收不到先 topic info -v。

R22 · ROS_DOMAIN_ID 和 ROS_AUTOMATIC_DISCOVERY_RANGE 各管什么？安全的域号范围？

来源：第 8 章 · 第 1 步 · 加入 2026-11-13 · 复习记录：

答案

Domain ID 是同一张网上的"频道号"：同域互相发现，不同域互相看不见；默认 0。DDS 用它算 UDP 端口，Linux 上安全范围 0–101（及 215–232），macOS 0–166；不想细算就取 0–101。

口诀：同号同频道，默认是 0；LOCALHOST 只看本机，STATIC_PEERS 点名找人。

R23 · 怎么换中间件？DDS 和 Zenoh 的发现方式有何不同？"看不见对方节点"按什么顺序排查？

来源：第 8 章 · 第 2–3 步 · 加入 2026-11-13 · 复习记录：

答案

export RMW_IMPLEMENTATION=rmw_fastrtps_cpp | rmw_cyclonedds_cpp | rmw_connextdds | rmw_zenoh_cpp，代码不改；全系统用同一个，DDS 与 Zenoh 互不相通。

R24 · rclpy.spin(node) 背后是什么 executor？等待集告诉 executor 什么？有哪三种 executor？

来源：第 9 章 · 第 1 步 · 加入 2026-11-13 · 复习记录：

答案

spin(node) = 创建单线程 executor、add_node、spin()：当前线程不停向 rcl / 中间件询问有无新消息、定时器是否到期，有就调回调。消息留在中间件里（不在客户端库排队），等回调来取，这样 QoS 才生效。

等待集只告诉"某队列有没有数据"，不告诉几条、谁先到；回调快时近似先来后到，慢时按话题轮转。一个慢回调会拖住同一单线程上的所有回调。

三种：SingleThreadedExecutor（默认）、MultiThreadedExecutor（线程池，并行度由回调组决定）、EventsCBGExecutor（Lyrical 新增，就绪事件进先进先出队列，省 10%–15% CPU，支持多线程和仿真时间，队列无上限）。一个 executor 可 add_node 多个节点。

口诀：spin 就是单线程 executor；快时先来后到，慢时轮转。

R25 · 两种回调组的规则？为什么"换成多线程 executor"常常没效果？服务死锁怎么用回调组修？

来源：第 9 章 · 第 2–3 步 · 加入 2026-11-13 · 复习记录：

答案

互斥组（MutuallyExclusiveCallbackGroup）：组内回调不能同时执行；可重入组（ReentrantCallbackGroup）：组内回调可并行，同一回调也能同时跑多份；不同组之间总能并行。未指定组的回调都在默认组，默认组是互斥组，所以只换多线程 executor 不分组，仍是串行。回调组对象要存住（self.xxx_group），创建实体时传 callback_group=。

分组原则：自己能否和自己并行 → 可重入 / 互斥；两个回调绝不能同时跑 → 放同一互斥组；需要并行 → 不同组。

修死锁：定时器和客户端放不同互斥组 + MultiThreadedExecutor：一个线程在定时器回调里同步等，另一个线程处理回复。控制回路单独一组（C++ 可交给单独 executor / 高优先级线程）。Python 有 GIL，多线程主要解决等待。

口诀：多线程不分组还是串行；等人的和被等的分开组。

R26 · 组件和普通节点有什么区别？组合（composition）带来什么好处？

来源：第 10 章 · 第 1 步 · 加入 2026-11-13 · 复习记录：

答案

组件 = 没有 main 的节点：编成动态库，运行时由组件容器进程加载（ROS 1 的 nodelet，ROS 2 统一成同一套 API，通常是 rclcpp::Node 子类，构造函数收 NodeOptions，用 rclcpp_components 宏 / rclcpp_components_register_nodes 注册）。构造函数里不做耗时阻塞的事，周期工作用定时器。目前是 C++ 特性。

好处：进程布局在部署时决定——分进程（隔离、好调试）或进同一容器（开销小、可进程内零拷贝）。命令：ros2 run rclcpp_components component_container、ros2 component load /ComponentManager <包> <类>、ros2 component list；容器可选 --executor-type multi-threaded | events-cbg、--isolated。

口诀：没有 main 的节点，进容器加载，进程怎么分部署时定。

R27 · 三种减少复制的机制各是什么、各有什么前提？

来源：第 10 章 · 第 2–3 步 · 加入 2026-11-13 · 复习记录：

答案
  1. 进程内通信：同一进程、两边 NodeOptions().use_intra_process_comms(true)，发布 publish(std::move(unique_ptr)) 交出所有权，订阅者拿到同一块内存（demo 打印地址相同）。交出后发布者不能再用。

  3. rosidl::Buffer（Lyrical）：C++ 里 uint8[] 等变长数组字段改为可挂后端的 Buffer，数据可留在 GPU / 厂商内存，解决"源数据不在 CPU"时前两者帮不上的问题；用法同 vector，需 Fast DDS 或 Zenoh 与对应后端。

口诀：同进程交指针，跨进程借内存，GPU 数据不回家。

R28 · ROS 2 有哪三种时钟？仿真时间怎么开？最常见的坑是什么？

R29 · 托管节点有哪四个主状态、五种转换？各回调该做什么？谁来触发转换？

来源：第 11 章 · 第 2–3 步 · 加入 2026-11-13 · 复习记录：

答案

主状态：Unconfigured（刚构造 / 出错退回）→ Inactive（配置好不干活：不处理话题、功能性服务请求立刻失败，可安全改配置）→ Active（干活）→ Finalized（待销毁）。过渡状态：Configuring、Activating、Deactivating、CleaningUp、ShuttingDown、ErrorProcessing。

转换：configure（on_configure：读参数、建通信、分配内存、连硬件）、activate（on_activate：激活发布者、开始处理）、deactivate（停止处理，硬件不断）、cleanup（释放 configure 申请的一切）、shutdown（任意主状态 → Finalized）。Active 中出错自动进 ErrorProcessing，on_error 成功回 Unconfigured、失败到 Finalized。构造函数里什么都不做（Nav2 约定）。

触发：除出错外都要外部监管者：ros2 lifecycle set <节点> <转换>、launch 事件处理器、Nav2 lifecycle_manager（按序启动 + bond 心跳，崩一个就有序降级）。

口诀：configure 准备好，activate 才开工；转换听外部指挥。

R30 · 一个点从源坐标系换到目标坐标系的公式？只平移和带旋转时怎么算？为什么用四元数？

来源：第 12 章 · 第 1 步 · 加入 2026-11-13 · 复习记录：

答案

\(P_{\text{target}}={}_{\text{target}}T_{\text{source}}\cdot P_{\text{source}}\)（左下标目标、右下标源）；串联 \({}_{B}T_{A}={}_{B}T_{E}\cdot{}_{E}T_{A}\)。变换 = 平移 \(t\) + 旋转 \(q\)，作用顺序先转后移：\(P_{\text{target}}=R\,P_{\text{source}}+t\)。

例：相机在底座前 0.1、上 0.3，无旋转，看到 (0.5,0,0) → 底座下 (0.6,0,0.3)；相机朝左转 90° 时先转成 (0,0.5,0) 再加平移得 (0.1,0.5,0.3)。

四元数 \((x,y,z,w)\)，不转是 \((0,0,0,1)\)，必须单位长度（手算后 normalize）。不用欧拉角：有万向节锁、插值不平滑、轴顺序约定多。存储传输用四元数，给人看再转欧拉角（quaternion_from_euler）。ROS 轴约定：x 前、y 左、z 上。

口诀：先转后移；四元数存，欧拉角看。

R31 · tf2 的树有什么规则？/tf 和 /tf_static 区别？REP 105 主干是什么、各段谁发布？

来源：第 12 章 · 第 2–3 步 · 加入 2026-11-13 · 复习记录：

R32 · URDF 由什么组成？四种常用关节？一个连杆的三种描述各给谁用？

来源：第 13 章 · 第 1–2 步 · 加入 2026-11-13 · 复习记录：

答案

link（刚体连杆）+ joint（连接父子连杆）组成一棵树，每个 link 一个坐标系。joint 写 parent、child、origin（关节角为 0 时子相对父的变换）、axis（转 / 移的轴）、limit（effort、lower、upper、velocity）。

口诀：link 是骨头，joint 连父子；visual 给人看，collision 给碰撞，inertial 给物理。

R34 · launch 文件里的"替换"是什么？为什么不能直接 if LaunchConfiguration(...)？列出常用的条件、包含、分组、事件写法。

来源：第 14 章 · 第 1 步 · 加入 2026-11-13 · 复习记录：

答案

launch 文件是描述不是脚本；LaunchConfiguration('x')、PathJoinSubstitution、FindPackageShare、Command、PythonExpression 都是替换：写文件时是占位，启动时才求值，所以 Python 里直接 if 拿不到值，要用 condition=IfCondition(...) / UnlessCondition(...)。

R36 · "实时"要求什么？哪些操作不能出现在实时控制回路里？为什么关节控制不用普通 ROS 节点写？

来源：第 15 章 · 第 1 步 · 加入 2026-11-13 · 复习记录：

答案

实时 = 准时：周期性更新、在截止时间前完成、抖动小（不是"快"）。关节环 0.5–1 kHz，晚了会抖动、撞击。

回路里的大忌：动态分配 / 释放内存；缺页（对策：启动时 mlockall + 预分配）；可能无限期阻塞的锁；日志、文件、网络 I/O。操作系统要 PREEMPT_RT（或 Xenomai），实时线程设高优先级、绑核。

普通 executor 调度复杂、有优先级反转、开销大，Python 还有垃圾回收和 GIL，不适合硬实时；所以快回路放进 ros2_control（C++、共享接口、无消息传递），话题留在边上。

口诀：实时是准时；不分配、不缺页、不阻塞、不 I/O。

R37 · ros2_control 由哪四部分组成？一个周期的三步？状态接口和命令接口的区别？怎么配置和启动？

来源：第 15 章 · 第 2–3 步 · 加入 2026-11-13 · 复习记录：

答案

控制器管理器 CM（装载 / 激活控制器，配对接口，update() 驱动回路，提供服务）；资源管理器 RM（pluginlib 加载硬件组件，管生命周期，read() / write()）；控制器（ControllerInterface 插件，每拍 update()）；硬件组件（System 多自由度读写 / Sensor 只读 / Actuator 单自由度读写）。

一拍：read() 硬件 → 状态接口；update() 控制器读状态、写命令接口；write() 命令接口 → 硬件。频率 = update_rate。

状态接口只读（position / velocity / effort / force）；命令接口同一时刻只能一个控制器占用。接口是共享变量，没有序列化和内存分配。

配置：URDF 里 <ros2_control name type="system"> 写 <hardware><plugin> 和每个 joint 的 command / state interface；控制器在 YAML（controller_manager: ros__parameters: update_rate, 控制器名: type:）；launch 起 ros2_control_node + ros2 run controller_manager spawner <控制器>；查看 ros2 control list_controllers / list_hardware_interfaces。换 mock_components/GenericSystem 或仿真插件，控制器不改。

口诀：CM 管节拍，RM 管硬件；read、update、write；命令接口独占。

R38 · 写一个 ros2_control 硬件组件要实现哪些函数？各生命周期步骤对应什么硬件动作？接口从哪来？

来源：第 16 章 · 第 1 步 · 加入 2026-11-13 · 复习记录：

答案

继承 hardware_interface::SystemInterface（或 Actuator / Sensor）的 C++ 插件： - on_init(info)：调父类 on_init，读 URDF <ros2_control> 参数、检查关节接口（→ UNCONFIGURED，不通信）； - on_configure：建立通信（串口 / CAN / EtherCAT）（→ INACTIVE，可读状态）； - on_activate：上电、松刹车，命令生效（→ ACTIVE）；on_deactivate 反之；on_cleanup 断开通信；on_shutdown / on_error； - read()：set_state("关节/类型", 值)；write()：get_command("关节/类型") 发给硬件。返回 SUCCESS / FAILURE / ERROR。

接口由框架按 URDF <ros2_control> 标签自动导出，名字 <关节>/<类型>。导出：PLUGINLIB_EXPORT_CLASS + 插件描述 XML + pluginlib_export_plugin_description_file(hardware_interface xxx.xml)。read / write 在实时回路里：慢通信放另一线程或异步组件；诊断信息用框架状态发布器或 get_node()。无硬件用 mock_components/GenericSystem。

口诀：init 读配置，configure 通信，activate 上电松刹车，read / write 每拍收发。

R39 · 关节轨迹控制器（JTC）的输入、两个入口和执行方式？差速控制器收发什么？写控制器时订阅回调和 update() 怎么交换数据？

来源：第 16 章 · 第 2–3 步 · 加入 2026-11-13 · 复习记录：

答案

JTC：输入关节空间路点（时刻 + 位置，可选速度 / 加速度），按时间插值、每拍算当前目标；入口 <名>/joint_trajectory 话题（无反馈）和 <名>/follow_joint_trajectory 动作（FollowJointTrajectory，有反馈结果，MoveIt 用）；新轨迹替换旧的，动作新目标使旧目标 abort；位置接口直接转发，速度 / 力矩接口经 PID；实时安全、处理连续关节、取消可平滑减速。

差速：订阅 ~/cmd_vel（TwistStamped），按轮距轮径算左右轮速写命令接口；发布 ~/odom（nav_msgs/Odometry），可选发 odom → base_link tf。

写控制器：实现 command_interface_configuration() / state_interface_configuration() 声明接口，on_configure 读参数建订阅，update() 实时安全。订阅回调在普通 executor（非实时），update() 在实时线程，两者用 realtime_tools 的实时缓冲区交换，不能直接共享普通成员变量。级联：控制器导出参考接口给上一级写。

口诀：JTC 路点插值，话题无反馈动作有反馈；回调与 update 之间用实时缓冲区。

R40 · Nav2 有哪五个服务器、各做什么？"别名 + 插件"有什么好处？MPPI 怎么算速度？

来源：第 17 章 · 第 1 步 · 加入 2026-11-13 · 复习记录：

答案

规划服务器（全局代价地图上算全局路径：NavFn、Smac、Theta*）、控制服务器（局部代价地图上每周期算 cmd_vel 跟路径：MPPI、RPP、DWB…；ROS 1 叫局部规划器）、平滑服务器（修平路径、远离障碍）、行为服务器（清代价地图、原地转、等待、后退等恢复）、路线服务器（在预定义导航图上找路线）。都是动作服务器，算法是插件。

别名：行为树里写 FollowPath，配置里决定用 MPPI，参数在 FollowPath.<参数>；换算法不改树；同一服务器装多个插件共用一份代价地图。

MPPI：以上周期最优控制为基础随机采样一批扰动控制序列 → 前向模拟轨迹 → 插件式评价函数打分 → softmax 加权得新控制，迭代几次；评价函数不需凸、不需可导；支持差速 / 全向 / 阿克曼，100 Hz+。

口诀：规划算路、控制跟路、平滑修路、行为救急、路线走图。

R41 · 全局和局部代价地图有何区别？代价地图有哪些层？默认导航行为树遇到失败怎么做？

来源：第 17 章 · 第 2–3 步 · 加入 2026-11-13 · 复习记录：

答案

代价地图：二维栅格，格子代价为未知 / 空闲 / 被占 / 膨胀。全局：整张图、map 坐标系、给规划器 / 平滑器；局部：机器人周围滚动窗口、odom 坐标系（连续不跳）、给控制器 / 行为服务器。层：静态层（读 /map）、障碍层 / 体素层（激光、深度实时障碍）、膨胀层（障碍周围递减代价，配合 robot_radius / footprint）；过滤器做禁行区、限速区、优先车道。

默认 NavigateToPose 树：每秒重规划；规划失败清全局图、控制失败清局部图后重试；仍失败进入恢复子树依次清图、原地转、等待、后退，每次恢复后重试导航；整体最多重试 6 次；GoalUpdated 让新目标随时抢占。入口动作 NavigateToPose；服务器均为托管节点，由 lifecycle_manager 拉起；需要 map → odom → base_link。

口诀：全局在 map 给规划，局部在 odom 给控制；失败先清图，再转、等、退，最多六次。

R42 · move_group 需要哪三类配置？SRDF 写什么？它和机器人之间通过什么交互、哪些不由它提供？

来源：第 18 章 · 第 1 步 · 加入 2026-11-13 · 复习记录：

答案

URDF（robot_description：外形和关节）、SRDF（robot_description_semantic：规划组、末端执行器、预定义姿态、不需检查碰撞的连杆对）、MoveIt YAML（关节限位、运动学求解器、规划器、感知）；SRDF 和 YAML 用 MoveIt Setup Assistant 生成。

交互：读 /joint_states（自己不发布）、读 tf（需 robot_state_publisher）、通过 FollowJointTrajectory 动作把轨迹交给控制器（动作服务器不由 MoveIt 提供，是 ros2_control 的 JTC）。维护规划场景 = 机器人状态 + 障碍物 + 手持物体。

口诀：URDF 长相、SRDF 分组和免查碰撞、YAML 管参数；状态别人给，执行别人做。

R43 · MoveIt 规划流水线的步骤？路径和轨迹的区别？什么时候用 Servo？

来源：第 18 章 · 第 2–3 步 · 加入 2026-11-13 · 复习记录：

答案

请求（关节或末端位姿目标 + 位置 / 姿态 / 关节 / 可见性约束，默认查碰撞）→ 逆运动学（默认 KDL 数值雅可比）→ 规划器插件（OMPL 采样如 RRT；Pilz 工业 LIN / PTP / CIRC；CHOMP 优化）→ 规划请求适配器（如 CheckStartStateBounds 修起点）→ 时间参数化（TOTG，默认步长 0.1 s，起止静止，限值来自 joint_limits.yaml）→ FollowJointTrajectory 交给 JTC 执行。

路径 = 一串关节位形，无时间；轨迹 = 带时刻、速度、加速度，满足限制。规划器出路径，时间参数化变轨迹。

Servo：不规划整条轨迹，持续接收关节速度 / 末端速度 / 末端位姿指令实时转关节命令，带奇异点和碰撞减速、平滑、限位；用于遥操作、视觉伺服、学习策略持续输出末端运动。Python 用 MoveItPy：get_planning_component → set_start_state_to_current_state / set_goal_state → plan() → execute()。

口诀：路径没时间，轨迹有时间；整段用规划，持续用 Servo。

R44 · 从仿真切到真机，最少要改哪几样？仿真器怎么接入 ROS 2？

来源：第 19 章 · 总图与第 1 步 · 加入 2026-11-13 · 复习记录：

答案

上层（Nav2、MoveIt、策略）只认话题 / 动作 / ros2_control 接口，不改。要改：① URDF <ros2_control> 的 <plugin>（mock_components/GenericSystem → gz_ros2_control / mujoco_ros2_control → 自己的硬件组件）；② use_sim_time（仿真时全体 true、真机全体 false）；③ 传感器来源（仿真器经 ros_gz_bridge 等发标准话题 → 真实驱动）。

接入：关节经 ros2_control 仿真插件（read / write 读写物理引擎）；传感器经桥接成 sensor_msgs 话题；时间经 /clock。ros2_control 官方集成 Gazebo、MuJoCo、topic-based；社区有 Isaac Sim、Webots、AGX。Gazebo 版本搭配按 REP 2000，gz sim 自检。RL / VLA 多在 MuJoCo / Isaac Lab 里直接训练，再经 ROS 2 节点在仿真版 ros2_control 上验证，最后换真机（sim-to-real）。

口诀：上层不动，换插件、关 sim time、换传感器来源。

R45 · ROS 2 系统怎么用 Docker 部署？Wi-Fi 传大消息为什么会卡 30 秒、怎么办？

来源：第 19 章 · 第 2–3 步 · 加入 2026-11-13 · 复习记录：

答案

Docker：FROM ros:lyrical-ros-base（机器人上不要 desktop）→ rosdep + colcon 编译 → 多阶段构建只拷 install/ → docker compose 编排子系统，常用 network_mode: host（默认网络组播常不通）→ restart: always / systemd 开机自启；ARM 板子用交叉编译或 buildx；也可打 deb 包。

卡顿：大消息被拆成多个 IP 分片，丢一片后其余分片堆在内核缓冲区，Linux 默认 30 s（ipfrag_time）才放弃重组，缓冲区满了新数据进不来。对策：Best effort QoS、调小 net.ipv4.ipfrag_time、调大分片 / 接收缓冲区、压缩图像或降分辨率帧率；远程跨网用 Zenoh / 发现服务器。联网产品开 SROS2（认证、加密、访问控制）；急停是硬件回路。

口诀：最小镜像多阶段，host 网络开机起；大消息 Wi-Fi 卡三十秒，尽力而为加压缩。

R46 · 学习策略节点的输入要注意什么？为什么要"快慢分离"，怎么做？

来源：第 20 章 · 第 1–2 步 · 加入 2026-11-13 · 复习记录：

答案

输入：相机用 qos_profile_sensor_data（Best effort）订阅；message_filters 近似时间同步按采集时间戳配对图像和 /joint_states，多机要 NTP / PTP 对时；cv_bridge 转图像，颜色顺序 / 分辨率 / 归一化与训练一致；末端类输出用 tf 对齐到 base_link，外参来自手眼标定。

快慢分离：推理 100–300 ms（5–10 Hz），关节命令要 50 Hz+。推理放回调组 A（单独线程 / 进程，GPU），产出动作块 + 起始时刻写入短锁缓冲区；执行放回调组 B 的 50 Hz 定时器，取当前步、块间平滑衔接（时间集成 / RTC）、限幅后发出；多线程 executor。推理更重时放单独进程或 C++ 组件，用进程内通信 / rosidl::Buffer。

口诀：图像尽力而为，时间戳用采集时刻；推理慢执行快，分组分线程。

R47 · 策略输出该接哪个控制器？JTC 的 2026 新功能如何帮助动作块衔接？策略节点的安全措施和生命周期？

来源：第 20 章 · 第 2–3 步 · 加入 2026-11-13 · 复习记录：

答案

关节位置逐点 → forward_command_controller（平滑全靠自己）；短轨迹 / 整个动作块 → JTC joint_trajectory 话题（R-M10）；末端位姿块 → cartesian_trajectory_controller；末端速度 → MoveIt Servo；底盘速度 → diff_drive cmd_vel。

JTC（GSoC 2026，gsoc2026_physical_ai.rst）：allow_trajectory_replacement（默认开）把新轨迹与执行中的旧轨迹融合：前缀 + 解析采样的桥接点（带真实速度加速度）+ 新路点 + 未覆盖关节的后缀；positions_upsampling 在非实时回调里解三对角方程得节点速度，实时回路三次埃尔米特插值得 C2 轨迹，可按策略频率补时间；块起点速度钳到上一个命令速度，消除接缝停顿；5 Hz 抓放 jerk 峰值约降为 1/4。

安全：限幅；动作块过期（如 >0.5 s）就保持当前位置，不外推；输入断就停；关键节点退出整体停机；急停在硬件。托管节点：configure 加载权重并预热，activate 才动，deactivate 保持不动。测量：tracing 量端到端延迟看 p99，bag 录输入和动作。

口诀：短轨迹给 JTC，末端速度给 Servo；过期即停，量 p99。
